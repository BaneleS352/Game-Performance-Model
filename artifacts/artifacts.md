# `artifacts/` Folder Guide

## Folder purpose

Runtime output and audit storage. Artifacts are generated by notebooks, the
upload pipeline, dashboard export, and tests. They are not source code.

## File inventory and subfolders

| Path | Contents | Producer |
|---|---|---|
| `processed/` | `clean_game_daily.pkl` | notebook 01 / upload pipeline |
| `features/` | `historical_snapshots.joblib` | notebook 02 / upload pipeline |
| `models/` | `training_results.joblib` | notebook 03 / upload pipeline |
| `reports/` | predictions and model/business reports | notebook 04 / manual export |
| `dashboard/` | compiled dashboard, `dashboard_data.json`, `dashboard_data.js` | dashboard export/Vite build |
| `uploads/<run_id>/` | run-scoped cleaned data, snapshots, models, predictions, logs, reports, and staged dashboard | upload pipeline |
| `pytest-tmp/` | test-generated temporary files | pytest; disposable |
| `artifacts.md` | folder guide | Markdown |

## Key processes

The upload pipeline writes a complete run under a timestamped id and publishes
latest artifacts only after success. Dashboard files use temporary copies and
atomic replacement. Binary artifacts are Python/dependency-sensitive and should
not be loaded from untrusted sources.
